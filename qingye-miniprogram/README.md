## 定位与附近球场

首次进入首页，在隐私保护指引同意流程之后请求 `wx.getLocation({type:'gcj02'})`。取得位置后，首页推荐有坐标的附近球场，球场列表默认按直线距离升序；定位拒绝、系统关闭、超时等情况可手动选地区和搜索。首次已拒绝不会反复请求，用户可以主动前往授权设置。

定位只保留在内存，5 分钟内复用，不落盘、不随反馈或球局上传，不开启后台持续定位。再次进入页面会使用当前会话位置，主动点重新定位会跳过缓存更新。

现有数据只有 65 条带来源经纬度，其坐标系未独立核实，附近距离明确显示“约”，只作粗略选场排序。其余 377 条排在有坐标资料之后，显示“距离待补充”；不填城市中心、不显示假精确公里数。球场位置不等于发球台或果岭 GPS，不用于实时击球测距。

后台可新增或修正经纬度、坐标系和来源说明；标记已核实必须同时提供坐标系和核实说明。当前仅 GCJ-02 坐标可直接交给 `wx.openLocation` 导航；坐标系未知等情况提供地址复制，在地图 App 搜索确认。

上线需在微信公众平台配置相关接口权限和《用户隐私保护指引》，描述“用于展示附近球场并按距离排序”，以平台实际类目及接口权限审核结果为准。代码已声明 `scope.userLocation` 和 `requiredPrivateInfos: ["getLocation"]`，不能靠占位 AppID 获得权限。

## 后台与反馈连接

`backend/` 是独立的网页后台与接口服务，保留球场、图片、账户角色、反馈回复、审计和备份功能，并增加坐标管理。它不随小程序代码上传，不把管理员密码或数据库打进小程序。

```sh
python3 backend/server.py --port 8767
```

仅监听本机 `127.0.0.1`，管理地址 `http://127.0.0.1:8767/manage/`。首次管理员账户需由项目所有者自己初始化。原 H5 后台数据库没有复制进公开源码；本机完整备份单独保管。

正式连接步骤：
1. 把该后台部署到自己的服务，通过反向代理提供 HTTPS；生产环境不直接公开 Python 开发服务端口。
2. 设置 `QINGYE_PUBLIC_ORIGIN=https://你的服务域名`；反向代理保留 Host 与 Origin。没有该配置时仍只接受本机主机名，不放开来源白名单。线上会话 Cookie 会带 Secure。
3. 在小程序 `miniprogram/config.js` 填写 `apiBase`，并在微信后台配置相应 request、downloadFile 等合法域名；图片须使用允许的 HTTPS 域名。
4. 测试新增球场、上传图片、发布/隐藏和反馈回复。管理端仍通过浏览器操作，小程序只访问公开球场/图片和自己的反馈回执接口。

未填写 `apiBase` 时可以离线看球场、记分、看已打包银涛图、保存反馈草稿；反馈页面明确说明尚未发送。接通服务后可提交、查询处理状态和回复。微信登录与组队同步由新增云开发模块负责；当前尚未配置部署。球场资料/反馈后台管理员账户与球友微信身份独立。

## 旧记录与新增功能

旧 H5、浏览器预览及微信设备存储相互独立。本轮保留已有记录，不清空本机数据；用户端导出/恢复入口及对应说明已经移除。原有迁移代码保留用于兼容读取旧数据，不再提供用户操作入口。

- 微信好友通过用户主动转发邀请卡片或小程序码加入，每组最多 4 人；活动可有多个组互看成绩。常用球友来自实际注册的同组成员，旧临时昵称不冒充微信好友。
- 云函数验证真实微信身份和小组记分员权限；断网先保存本机，恢复网络再同步。重复提交可安全重试，其他设备的较旧版本不能覆盖新成绩。
- 我的页面增加差点入口，自动基础参考值与手动设置分别保存。缺少评级等必要信息时提示补齐；目前不是官方认证 WHS 差点。
- 这些联机能力尚未在真实云环境和两台微信设备联调，不能将浏览器预览当作已上线的多人同步服务。
